Skills

Write the rules once, use them everywhere

A skill is a folder with a SKILL.md file: what it does, what it reads and writes, what it needs, and the steps it follows. Install the core skill first. Team skills build on it.

1 · Install the core skill

docusign-agreements

Core · all teamsClaudeChatGPTCopilot StudioGemini
What it does: sets the read-first, approve-before-write rules, the tool order and the output format. Why it is needed: without it, assistants guess dates, mix up envelope and agreement data, and can send without asking.




2 · Team skills


Team skills are skills grouped by the team that uses them: Sales, Procurement, HR, Legal, Finance & RevOps, CX FINS and IT & Admin. Each one is a SKILL.md you add alongside the core skill.
Skill or automation? A skill runs when you ask for it in chat. An automation runs on a schedule with nobody asking, so it needs a scheduler (Claude scheduled tasks are confirmed). Both follow the same rules, and any write still waits for your approval.

Guardrails and FAQ
Built so you can check the answer




Does it invent numbers?
No. Every prompt and skill says to label missing values. Check high-stakes figures against Docusign before you act.


Who approves sends?
You do. Drafts are saved as created, nothing is sent, reminded or triggered until you say yes.


What can it see?
Only what your Docusign user can see. The server acts as you, so an agent cannot see more than you can.


Is this legal advice?
No. The prompts summarize agreements and flag differences. Legal decisions stay with your legal team.


Do I need to set anything up for Copilot?
Your admin connects Docusign once. Then copy a prompt into Copilot and add the names.


Where does my data live?
Regional hosting in the US, EU, Australia, Canada and Japan (reported). Once data reaches your AI tool, that tool's data terms apply.

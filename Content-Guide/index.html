2. The starting prompt

Paste the base file into Claude, then describe your content. Ask for one stage at a time.

Here is an existing Docusign workshop HTML page [paste file]. Create a new lab on [your topic] using the exact same design, CSS, and components. My outline: - Stage 0: Before you begin (prerequisites: [list]) - Stage 1: [Title] — steps: [list] - Stage 2: [Title] — steps: [list] Use .h-check headings for steps, .card for content, .expect for checkpoints, .warn for gotchas. Generate Stage 1 only. Return just the <section> HTML, not the full file.
Ask for one stage at a time. Easier to review, and cheaper to regenerate if something is wrong.

3. Editing an existing section

Never paste the full file for a small change. Paste only the relevant section.

Here is section 1.3 of my workshop HTML [paste only that section]. Changes: 1. Rename "Capabilities" to "Tools" everywhere in this section. 2. Update the checkpoint text to: "[new text]" 3. Add a .warn block after step 2: "[warning text]" Return only the updated HTML for this section.

5. Token efficiency tips

  • Paste only the section you're changing, not the full file. The CSS alone is 220+ lines Claude doesn't need to re-read.
  • Write content as plain bullet points first, then ask Claude to wrap in HTML. Iterating plain text is cheaper.
  • Keep one conversation going for a single lab — context stays warm.
  • Ask Claude to return only the changed snippet — "return only this section, not the full file" saves 800+ lines of unchanged output.
Biggest trap: pasting the full file and asking Claude to "update it." Instead, paste the 10–20 line section, get the fix, apply it manually. 30 seconds and a fraction of the cost.

6. Publishing

  1. Open locally in Chrome and check all sections render correctly.
  2. Test the Copy button on at least one prompt block.
  3. Confirm all screenshots load — no broken images.
  4. Resize to mobile width (~375px) — sidebar hides, layout stacks vertically.
  5. Create a folder in the repo root, add your HTML + assets/ subfolder.
  6. Commit and push to your repo. GitHub Pages deploys in ~60 seconds.
SSO: if git push returns 403, go to GitHub Settings → Applications, find GitHub CLI, and authorize the docusign org.
